第一批 24 篇讲"它是什么、怎么跑、为什么这样设计"；第二批讲"我用它做成了什么"。

为什么要有第二批

光讲机制，读者学不会用；光讲案例，读者不知道为什么。两批合起来才是一套完整的"从 0 到 1"。

每个案例的写法（沿用笔记体）

  • 四行笔记头（我带着的问题 / 读之前我以为 / 读完的答案 / 三个自测问题）
  • 人话版开场
  • 真实过程：需求 → 第一版 → 失败 → 改版 → 结果
  • 术语小抄 + 我还没搞懂
  • 本文依据（代码路径、命令输出、数据）

发布顺序

第一批 24 篇发到第 10 天左右，开始穿插案例篇；也可以先把 25（内容生产）提前，因为它最贴近"关注我的人想学的东西"。
