为什么它总要问你"用哪个目录"

版本 v1.1 ｜ 时间待补 (Asia/Shanghai) ｜ 依据：官方仓库 docs + 本机 dsh 实测
学习笔记 ｜ 第 5 站 ｜ 我带着的问题：新装的界面为什么先让我选目录，不选就不让说话？
读之前我以为：目录就是个路径，换个地方干活而已。
读完我的一句话答案：选目录是在给这次会话落项目身份，身份定了才开工。
读完我能答出来的三个问题：1 会话目录名是怎么从路径编出来的？ 2 改目录为什么不会把已经开着的终端也切过去？ 3 目录被挪走之后，为什么症状是"发什么都不回"？（答不出就说明我没学会，这篇先不发）
系列第 05 篇 ｜ 版本 v1.1 ｜ 2026-11-08 ｜ 依据：本机实测 + 系列资料 ｜ 修订：改为学习笔记体

先说人话版。装完打开界面，我第一件事是打字，结果输入框是灰的、点不动，它非要我先挑一个文件夹。我第一反应是这功能没做完。后来才明白，挑文件夹那一步是在回答一个问题：这次聊天算在哪个项目上。答完它才肯让我打字。

新装完 DSH，第一次打开 Web UI，我做的第一件事是打字——然后发现输入框是灰的，点不动。

它让我先"选择工作区"。

后来我去翻了文档和本机的会话目录，才发现那个灰色的输入框不是半成品，是整个设计里最硬的一块：我在选的不只是一个路径，是在给这次会话落一个身份。

我原来的判断

我原来判断：目录就是个路径。它决定我读文件从哪儿开始找、跑命令在哪儿跑，仅此而已。换个目录，等于换个地方干活，跟"这是一次什么会话"没关系。

现在的判断：目录是项目身份。一次会话的身份在它诞生那一刻就写死了，之后能改的是"执行位置"，改不了"这是哪个项目"。

先把官方那句话拆开

架构文档里有一句很长的话，我读了三遍才拆明白。原文大意是：工作目录提供用户上下文和执行路径，但不改变原始项目身份、不改变沙箱可写根、也不改变已经在跑的进程的目录。

一句话里有三个"不改变"，这才是重点。

它说的是：目录这东西在系统里同时扮演两个角色。一个角色是"上下文"——模型要知道自己在哪儿、相对路径以谁为准。另一个角色是"执行路径"——新起的进程在哪儿跑、文件操作以谁为基准。

而另外三件事被钉死了：项目身份、沙箱可写根、已有进程的目录。它们不跟着目录走。

能变的和钉死的同时存在，是我想写这篇的原因。

会话、目录、项目身份：其实是两套状态

工作目录的子系统文档写得更直白：会话的不可变头部标识原始项目；而"工作目录变更"这个事件，记录的是后续那些基于目录的操作实际使用的目录。

也就是说，一个会话身上有两份目录信息：

第一份在头部里，不可变，代表"这次会话属于哪个项目"。它是身份。

第二份是一条可以追加的事件，代表"现在我在哪儿干活"。它会变，而且变的时候会留下记录。

为什么要拆成两份？我的理解是：身份不能变，位置必须能变。

身份要是能改，归档就乱了——同一个会话今天算在 A 项目、明天算在 B 项目，出事时查不到它到底改过谁的文件；沙箱写根要是跟着位置走，那切个目录就顺手扩大了权限，安全模型直接失效。

但位置又必须能变，因为真实工程就是会跨目录：单仓里的子包、生成的产物目录、隔壁那个共享库。

这两份谁管什么，文档分得很清楚：

相对路径的文件操作、新启动的进程、指令发现（比如根目录那个给 agent 看的说明文件）、技能、文件补全——都看当前目录。

而沙箱的可写根、项目归属——锚在原始项目上。

最容易被忽略的一条是：已经开着的终端和持久 shell 保留它们自己的目录。改会话目录，不会去把某个正在跑的 shell 也 cd 过去。这个设计很克制，也很符合直觉——进程的目录是进程的，不是会话的。

一手：这套设计在磁盘上是看得见的

理论说完，说我在自己机器上看到的东西。这部分我自己最看重，因为全部可以复核。

本机会话都存在两个目录下，名字长这样：两个短横、一段把斜杠换成短横的路径、再两个短横。比如主工作区那个，就是双横线加用户目录一路编码下来，最后以两个短横收尾。

我一开始以为这是随机哈希，直到我试出了规律：把会话的工作目录路径末尾补一个斜杠，把所有斜杠替换成短横，再在两端各补一个短横——正好就是文件夹名。

我拿全部 186 个会话验了一遍这个公式，零例外。

（真实路径里带我的用户名，我就不贴了，规律如上，拿自己的目录一套就知道。）

这件事的意义不只是"命名整齐"。它说明存储层是拿目录当分区键的——官方文档里那句"存储后端以此作为目录键"就是这意思。一个目录一个分区，谁也污染不到谁。

数字也对得上：186 个会话，182 个在默认工作区下，4 个在另一个工作区下。两个分区泾渭分明，没有一次串门。

还有一个更硬的证据。

这 186 个会话里，有 146 个的头部带着父会话 id、来源标记是子代理、委派深度是 1。也就是说它们不是我自己开的会话，是 agent 派生出去的子会话。

我把所有能找到父会话的 147 个会话（含一个深度 0 的边界情况）逐个比对工作目录字段：147 个，全部与父会话完全一致，0 个不同。

子会话继承父会话的目录，这不是我推测的，是磁盘上的 147 比 0。

顺带纠正一个我一开始找错的地方：这个字段不叫什么 identity 下面套 cwd，它就平铺在会话头部，名字直接叫 cwd。同级的还有创建时间、格式版本、委派深度、预设名。我第一次按名字去找，扑了个空。

于是"为什么总问你目录"有答案了

现在回到那个灰色输入框。

新会话在创建时没有头部目录——它还不知道自己属于哪个项目。这时候系统用配置里的兜底目录；如果没有配兜底，就用启动进程时所在的目录。

而 Web UI 里新开的会话两者都没有：它不是从某个目录启动的，也没配兜底。所以它没有目录，没有目录就不能确定相对路径、不能确定沙箱写根、不能确定归档位置——于是输入框不可用，直到选好一个。

所以那句"选择工作区"，翻译过来是：这次工作算在哪个项目上。

你选了之后，这个会话的身份就落定了，之后它归档在哪个分区、沙箱能往哪儿写、相对路径以谁为准，全都跟这个选择绑定。

顺带解释一个很多人注意到的反差：命令行那个一次性模式从来不会问你目录。

不是它更聪明，是它有得继承——它就是你在哪个目录敲的命令，启动目录天然可当兜底。Web UI 没有这个来源，所以只能问。

还有一个经常被混淆的操作：能不能加目录。命令行那个一次性模式确实有一个"额外目录"的参数，但它的作用是"在受限写入模式下额外允许一个绝对目录"——也就是扩大沙箱可写根。它不放宽项目身份。

加目录不等于换身份。文档把这两件事分开写，我第一次读的时候把它们合并成一件了。

模型看到的是什么

这一段有个很具体的好处：官方把模型看到的原话给出来了。

当前工作目录会以一行文本进到请求里，格式是"当前工作目录：加一对引号包住的绝对路径"。

三个细节我记下来了：

第一，它是"必需的"用户上下文快照，即使你把可选的运行时上下文关掉了，它也还在。换句话说，这个信息不给关。

第二，它永远不进系统提示词。这看着像洁癖，其实是缓存考虑——目录变了只在后面追加，不去动稳定的系统提示词前缀，缓存才不会整段失效。

第三，改目录的时候，系统会尝试往 agent 的收件箱里塞一条通知。如果这条通知在投递前被取消或者被丢弃，没关系：目录变更事件本身留着，下一次被接纳的请求照样能拿到当前值。

工具面上只有一个可选参数，就是那个 cd。也就是说模型想换目录，只有这一条路，而且它换的是"后续操作的位置"，不是身份。

代价和坑

这套设计很干净，但代价是实打实的。

最常见的一种：目录没了。如果当前目录不存在，系统会尝试恢复原始项目；如果连原始项目也不在了，提示词组装会拒绝每一次模型回合——包括你只是想聊两句的那种回合。

翻译成人话：你把那个文件夹改名或者删掉，这个会话就彻底不能用了，症状是"我发什么它都不回"，而不是报错。文档给的解法是恢复原目录，或者用接口显式选一个存在的绝对目录。

第二个坑：改目录不会迁移已有的终端和持久 shell。你在旧目录开的 shell 还在旧目录，改完之后新起的才在新目录。第一次遇到会觉得"它怎么不听话"，其实是两层所有权分开的必然结果。

第三个坑：沙箱可写根锚在原项目。你把目录切到别处，不等于拿到了别处的写权限。这两件事一个是"我在哪儿干活"，一个是"我被允许碰哪儿"。

我错在哪，以及没验证的部分

我错在把"选目录"当成一次 UX 摩擦。它不是摩擦，是权限和归档的锚点——先定锚，再开工。

没验证的部分我说清楚：

一，同一个任务在两个目录下跑，行为会不会不一样，我没做这个对照实验。那要真发两次模型请求，按项目纪律我没跑。所以文中关于"上下文变了"的说法，全部来自官方文档和配置机制，不是我实测出来的差异。

二，换目录之后旧会话能不能续上，我没逐个验证。机制上工作目录是会话级事件、可以重放，一次性模式也有按 id 续会话的参数，但我没真跑过。文中我只写了机制，没写结论。

三，父子继承的规则我是"文档原话加磁盘证据"两头对上的：文档说省略目录时会捕获父会话的当前目录，磁盘上是 147 比 0。但"子会话显式传一个不同的目录会怎样"，我只看到文档说相对路径按父会话解析，没实测过绝对路径的情况。

下一篇

下一篇我想讲清楚"会话文件到底存了什么"：为什么它是追加日志、为什么改不动、为什么升级要有迁移、以及那些看起来像重复的记录到底在干什么。手上 186 个会话、一个格式版本号，够拆了。

术语小抄

工作目录：这次会话现在在哪个文件夹里干活，相对路径和命令都按它算。

项目身份：这次会话属于哪个项目。它在会话出生时就写定，之后不能改。

头部：会话文件开头那段一次性写好的元数据，里面有创建时间、格式版本、项目身份和 cwd。

沙箱可写根：这次会话被允许写入哪些目录。它锚在项目上，跟着目录切来切去也不会放大。

我还没搞懂

同一个任务在两个不同目录下跑，行为到底会不会不一样？我没做这个对照，那要真发两次模型请求。

换目录之后旧会话还能不能续上？机制上目录是会话级事件、可以重放，可我没真跑过。

子会话显式传一个不同的绝对路径会怎样？文档只说相对路径按父会话解析，绝对路径我没看到。

你有没有遇到过"发什么它都不回"、最后发现是目录被挪了的情况？或者你更想让我拆哪一块，留言说，我按票数排。
