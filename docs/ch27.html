五步迁移法：把这套方法搬到任何业务

版本 v1.3 ｜ 2026-11-08 15:00 (Asia/Shanghai) ｜ 依据：OPT 大方向 v1.0 + 46 个原子场景 + 本工作区实践
系列第 27 篇 ｜ 版本 v1.3 ｜ 2026-11-08 ｜ 依据：OPT 大方向 v1.0 + 46 个原子场景 + 本工作区实践
学习笔记 ｜ 第 27 站 ｜ 我带着的问题：这套"一人 + 一支 agent 团队"的做法，是不是只适用于网站出海？换个行业还能不能用？
读之前我以为：它是给技术人、给做网站的人用的，别人用不上。
读完我的一句话答案：它是一套"把业务拆成原子、再配角色和闸门"的方法；业务可以换，零件不换。
读完我能答出来的三个问题：1 这套方法的五个零件是什么？ 2 五步迁移法每一步的产出是什么？ 3 什么样的业务不该用它？（答不出就说明我没学会，这篇先不发）

先说人话：如果你不是做网站的，这篇是写给你的。方法不是"网站出海攻略"，是"怎么把你手里那摊事拆到 agent 能接手的程度"。我用网站出海做例子，是因为它流程最全、反馈最快；换成市场、销售、带孩子学习，零件是一样的。

读完你能做到

  • 说出五个零件，并指出缺一个会退化成什么样，各举一个例子
  • 用你自己的业务线，按五步各写一行产出，凑成一页纸
  • 判断你的业务属于"现在就能拆"，还是"三种不该用"里的哪一种，并说出依据

一、我原来的判断

我原来的判断：这套东西能用，是因为我懂技术、做的是网站。换个人、换个行业，就水土不服。

现在的判断：能不能用，不取决于行业，取决于三件事——流程能不能拆、结果能不能验收、错误能不能兜住。这三件事满足，行业只是换一套名词。

网站出海只是第一个样板间。样板间的价值不是让你住进去，是让你知道"水电怎么走"。

二、通用模式：五个零件

不管什么业务，这套方法都只由五个零件组成：

  1. 一条业务线：不是"公司所有事"，是一条能独立算账的线。比如"一个站"、"一条产品线的线索"、"孩子这学期的数学"。
  2. 原子场景（拆到不能再拆的一步）：把这条线拆到"单一产出、单一 owner（一个人负责）、可验收、可回滚、≤30 分钟"。
  3. 角色：把原子按职责分组，一个角色管一组原子；角色可以是 agent，也可以是人。
  4. 闸门（验收关卡）：每个原子有验收判据；不达标不放行。
  5. 记忆：规范、案例、数据沉淀成文档，下一次不用重新教。

这五个零件，缺一个都会退化成"用 AI 打杂"。没有业务线，就没有目标。没有原子，就没人能接手。没有角色，就全压在你身上。没有闸门，质量靠运气。没有记忆，每次从零开始。

三、五步迁移法

这一节回答：五步各要交什么。

第一步：选一条线（半天）

选一条能独立算账的业务线：有明确产出、有可看的数字、有止损线（亏到哪就停）。

产出：一页纸，写清"这条线的目标、周期、预算、止损"。

判断标准：如果这条线亏了，你能不能在一周内知道？能，就选它；不能，就再拆小。

第二步：拆七段（半天）

把这条线按时间顺序拆成 5—7 个阶段。网站出海是：选词、竞品、内容、建站、分发、数据、支撑。

产出：阶段清单，每段一句话说明"这段的产出是什么"。

判断标准：每个阶段结束时，都有一个能拿在手里的东西。

第三步：拆原子（一天）

每个阶段往下拆，拆到满足五条硬标准（单一产出、单一 owner、可验收、可回滚、≤30 分钟）。

产出：一张原子表（就像我们那张 46 行的 CSV，表格文件），每行有输入、输出、owner、验收判据、失败处理。

判断标准：随便挑一行，交给一个没做过的人，他看完知道要做什么、做完你知道该不该过。

第四步：配角色（半天）

把原子按职责分组，形成 5—8 个角色。每个角色写一页：职责、负责哪些原子、交付物、验收判据、红线。

产出：角色卡（agent 的提示词或人的岗位说明）。

判断标准：每个原子都有且只有一个 owner。

第五步：设闸门（半天）

给每个原子加验收判据，能机器查的写成脚本，不能的写成清单；再加三道全局闸门：成本、合规、上线。

产出：闸门清单 + 检查脚本。

判断标准：一个不合格的交付物，没法悄悄流到下一步。

五步做完，大概两到三天。之后每天跑原子、每周复盘，慢慢把重复的原子变成插件。

四、四个不同的人怎么用

这一节回答：换四种人，零件怎么摆。

市场专员：把"内容 + 线索"拆成原子

业务线：一条产品线的内容获客。
七段：选题、素材、写作、分发、线索捕获、跟进、复盘。
原子举例：找 20 个客户常问的问题、写一篇对比文、把文章改成 3 条社媒帖、整理本周线索来源。
角色：选题侦察、内容工、分发员、数据员。
闸门：事实核查、品牌口径、线索表单可用。

她不需要会写代码，只需要把"什么算好"写清楚。

销售：把"线索研究 + 跟进"拆成原子

业务线：一个季度的重点客户。
七段：名单、背景研究、需求判断、首次触达、跟进、报价、复盘。
原子举例：抓一家公司的公开信息、整理决策人、写一版开场话术、准备三个异议回答。
角色：线索研究员、话术工、跟进助手。
闸门：信息有来源、话术不夸大、报价有人审。

关键不是让 agent 替她聊客户，是让她在见客户前十分钟拿到一页纸。

宝妈：把"孩子学习"拆成原子

业务线：这学期数学。
七段：诊断、计划、讲解、练习、错题、复习、评估。
原子举例：找出这周错的 5 道题、按知识点归类、生成 3 道同类题、写一段讲解、做一张错题卡。
角色：诊断员、讲解员、出题员。
闸门：答案正确、难度匹配、孩子能听懂。

这里最重要的不是"AI 讲课"，是"每天十分钟，知道今天该补哪"。

一人公司：把"网站出海"拆成原子

这就是我们那张 46 个原子的表：选词、竞品、内容、建站、分发、数据、支撑。八个角色，第一周先跑 10 个原子。

五、什么业务不该用它

三种情况，别硬上：

  1. 结果没法在一周内验证：比如品牌建设、长期研发，反馈太慢，拆了也调不动。
  2. 错误代价不对称且不可逆：医疗诊断、法律意见、资金划转，agent 可以准备材料，但最后一步必须人。
  3. 流程还没稳定：一天改三次的流程，先别拆原子，先把流程定下来。

这三种不是"以后再说"，是"现在就不适合"。

六、这本书的用法

前面 24 篇讲原理，25 和 26 讲延伸和用途。这一篇讲迁移。接下来我会用"网站出海"做第一个完整案例，把 46 个原子真的跑一遍；跑通之后，再换行业套同一套零件。

所以你读这本书可以有两种读法：

  • 学原理：从 01 读到 24，知道 DSH 是什么、怎么跑。
  • 搬方法：直接读 26、27，然后拿你自己的业务线，按五步拆一遍。

两种读法不冲突：原理让你知道边界，方法让你能用起来。

落地案例：用五步拆你自己的业务，产出一页纸

场景：你有一条能独立算账的业务线，想按五步法拆一遍。但不知道拆完的产出长什么样。

做法：一页纸分五块。第一块写这条线的目标、周期、预算、止损。第二块写五到七个阶段，每段一句话。第三块每个阶段写三个原子，每个原子写清输入、产出、验收。第四块给每个原子写一个 owner。第五块写三道闸门：成本、合规、上线。

验收：随便挑一个原子，交给一个没做过这件事的人，他看完知道要做什么，你看完知道该不该过。做不到，说明这个原子还太大，回去再拆一层。原子先写十五个就够，别一次写四十六个。

耗时：两天，第一天拆到原子，第二天配角色和闸门。

读完这一篇，你应该能拿一页纸，把自己的业务拆到别人能接手的地步。

术语小抄

  • 业务线：能独立算账的一条线，有目标、预算、止损。
  • 原子场景：拆到不能再拆、且能验收的一步。
  • 角色：一组原子的 owner，可以是 agent，也可以是人。
  • 闸门：验收判据，不达标不放行。
  • 记忆：规范、案例、数据沉淀成的文档。

我还没搞懂

  • 不同行业的"七段"能不能总结成几种通用模板。
  • 原子拆到多细算够——太细管理成本高，太粗 agent 接不住。
  • 非技术用户怎么设闸门，才不会变成"自己给自己判卷"。
