DSH 系列 · 一周学习 + 两周发布排期

版本 v1.0 ｜ 2026-11-08 12:00 (Asia/Shanghai) ｜ 依据：24 篇提纲 + 现有 13 篇成稿 + 工作区内容发布 SOP
把原来的「12 周 24 篇」压成：学习 7 天 + 发布 14 天，每天 1—2 篇。

为什么能压

因为写和发已经拆开了：

  • 24 篇的稿子今天补齐（不用边学边写边发）；
  • 学习周只做一件事：把稿子里的东西真正跑一遍、验一遍；
  • 发布周只做一件事：配图、质检、排版、发、守评、复盘。

这比"边学边写边发"快，因为每天不用在三种状态之间切换。

目标：7 天后能回答三个问题——它是什么、它怎么跑、我能改哪里。每天"读 2—4 篇 + 动手 1 件 + 写 3 行笔记"。

发布前每篇的四道闸门（先学会，再发）

每篇发布前必须先过这四道，过不了就顺延，不占排期：

  1. 我读得懂：从头到尾读一遍，没有卡住的段落。
  2. 三问能答：笔记头里"读完能答的三个问题"，不看正文能答出来。
  3. 术语能讲：术语小抄里的词，能用自己的话讲给一个外行。
  4. 边界能说：能说清这篇里哪些是实测、哪些是推断、哪些还没验证。

发布前每篇的 6 步（每篇 30—40 分钟）

  1. 配图确认（≤9 张，宽 1200，路径存在）
  2. 质检：node tools/qc_article.mjs 文章.md，errors 必须 0
  3. 风险检查：安全/对比两类词面过一遍（05-发布包/04-发布前风险清单.md）
  4. 建 X 草稿（只建不发）：node tools/x_publish.mjs --auto 关键词
  5. 人工看一眼：标题、首段、图序、文末 CTA
  6. 定时发（08:30 / 20:30）

平台分配

  • X：主阵地，首发 + 独家感
  • 公众号：延后 3 天同步（P4 起开始搬 P1 的内容）
  • Substack：延后 3 天，英文标题可后补
  • Obsidian：发布当天归档到 03-已发布内容库，更新索引

六、把"学会"落到五件工作上（学习周的验收标准）

读文章只是手段，能用到工作里才算学会。7 天里每天挑一件真实工作跑一遍：

工作 用 DSH 做什么 验收
内容生产一条命令跑完：选题 → 初稿 → 质检 → 配图 → 建草稿产出一篇可发的草稿
Coding让它读仓库、改一个文件、跑测试提交一个真实的小改动
Vibe coding从一句需求到能跑的小页面/小工具跑起来一个原型
产品调研抓 3 个竞品页面、整理成对比表出一页调研结论
知识库管理新增一个专题、更新索引、同步镜像索引里能查到

每天做完记一句"卡在哪"，直接进 08-迭代/00-逐篇打磨清单.md 的反馈模板。

三、两周的硬约束

  1. 一天最多 2 篇：超过 2 篇，互动会摊薄，读者也记不住。
  2. 同一时间只推一个"钩子"：一天两篇要错开角度（一篇认知、一篇方法）。
  3. 发布前一天必须把两篇草稿都建好，当天只做"看一眼→发"。
  4. 每篇发后 48h 记录数据：曝光、收藏、涨粉、评论里被问最多的问题。
  5. 数据不好不临时改稿：先按排期发完，第二周再根据第一周数据调标题/钩子。
